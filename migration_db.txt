Secure-VibeCode -- Database Migrations
======================================

Schema is managed by Alembic (alembic/versions/). db.init_db() runs
`alembic upgrade head` on every backend startup, so a deploy applies any
new migrations automatically.

Changing the schema:
  1. Edit the models in backend/db.py.
  2. alembic revision --autogenerate -m "describe the change"
  3. Review the generated file in alembic/versions/, then commit it.
  tests/test_migrations.py fails if the models and migrations drift apart.

A database created before Alembic (via create_all) is stamped at the head
revision on first startup rather than re-created. It must already match the
current models; a very old database missing columns (e.g. scans.owner_token)
has to be dropped and recreated.

Manual commands (run from the repo root, DATABASE_URL set as for the app):
  alembic current
  alembic upgrade head
  alembic downgrade -1
