Secure-VibeCode -- Database Migration
======================================

This is the schema SQLAlchemy generates from backend/db.py (Scan and
Finding models) via Base.metadata.create_all(), run automatically by
db.init_db() on every backend startup (backend/main.py's lifespan hook).

It is NOT applied by hand -- it's here as a reference snapshot of what
init_db() creates. Tables are only created if they don't already exist,
so re-running it is always safe (no-op on an existing database).

Target database: secure_vibecode (Postgres, local via pgAdmin)
Connection: postgresql+psycopg2://postgres:****@localhost:5432/secure_vibecode
(see .env -- DATABASE_URL)

--------------------------------------------------------------------
1. scans
--------------------------------------------------------------------

CREATE TABLE scans (
	id VARCHAR NOT NULL,
	target VARCHAR NOT NULL,
	platform VARCHAR NOT NULL,
	status VARCHAR NOT NULL,
	created_at TIMESTAMP WITH TIME ZONE NOT NULL,
	PRIMARY KEY (id)
);

Columns:
  id          - UUID string, primary key, generated by the app (uuid4)
  target      - the GitHub repo URL or live URL that was scanned
  platform    - detected platform: lovable | bolt | replit | generic
  status      - scan run status (currently always "completed")
  created_at  - UTC timestamp the scan was created

--------------------------------------------------------------------
2. findings
--------------------------------------------------------------------

CREATE TABLE findings (
	id VARCHAR NOT NULL,
	scan_id VARCHAR NOT NULL,
	category VARCHAR NOT NULL,
	label VARCHAR NOT NULL,
	file VARCHAR NOT NULL,
	severity VARCHAR NOT NULL,
	what_it_means TEXT NOT NULL,
	why_it_matters TEXT NOT NULL,
	fix_prompt TEXT NOT NULL,
	status VARCHAR NOT NULL,
	PRIMARY KEY (id),
	FOREIGN KEY(scan_id) REFERENCES scans (id)
);

Columns:
  id              - UUID string, primary key, generated by the app (uuid4)
  scan_id         - foreign key -> scans.id (one scan has many findings)
  category        - e.g. missing_access_control, hardcoded_secret
  label           - short human label, e.g. "Row-Level Security not enabled"
  file            - file path or URL the finding was found in
  severity        - critical | high | medium | low
  what_it_means   - plain-language explanation (Explainer Agent)
  why_it_matters  - plain-language impact (Explainer Agent)
  fix_prompt      - copy-pasteable fix instruction (Fix-Prompt Agent)
  status          - open | resolved (flipped by the /rescan endpoint)

--------------------------------------------------------------------
How this actually gets created
--------------------------------------------------------------------

1. The database "secure_vibecode" itself was created once, manually,
   since Postgres requires connecting to an existing database (the
   default "postgres" db) to run CREATE DATABASE:

     CREATE DATABASE secure_vibecode;

2. Every time the FastAPI app starts (uvicorn backend.main:app), the
   lifespan hook in backend/main.py calls db.init_db(), which runs
   Base.metadata.create_all(bind=engine) -- this issues the two
   CREATE TABLE statements above if they don't already exist.

There are no Alembic migrations in this project yet -- schema changes
are made by editing the SQLAlchemy models in backend/db.py directly.
Since create_all() only adds missing tables and never alters existing
ones, changing a column on an existing table requires either dropping
the table manually or introducing Alembic migrations.
